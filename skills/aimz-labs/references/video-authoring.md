# Video authoring checklist

Read the selected model **and input mode** before writing: its current official Markdown guide, current model metadata and the actual installed/public input schema. Record the source URL and observation date. Check reference order, native audio capability, duration/frame grid and editable inputs. If a publisher provides no Markdown guide, record that limit and use its official documentation; never invent a guide or copy another model's syntax.

For this release, verified primary Markdown entry points are [MiniMax H3](h3-r2v.md) and [YuE2](yue2-instrumental.md). Other model families require their own current publisher guide. These notes are AIMZ authoring policy, not additional provider capabilities.

Before each video:

1. State the visible starting state, one plausible action progression and the ending state. Match food/object state, screen direction, lighting and object count across joins. Generate needed close views and the ending inside the video.
2. Request natural synchronized Foley and quiet ambience. Prohibit BGM, score, soundtrack, instruments, song and singing. Preserve only explicitly requested dialogue. Keep requested music as a separate file/track.
3. Keep character, space, prop and rendering references separate, with actual input order. Empty space references contain no people, characters, animals, hands or reflected figures. Plan useful distinct generated camera angles with consistent geometry.
4. Keep originals. Do not conceal defects using spatial crops, enlargement or panning crops. Time trims, whole-frame aspect-preserving resizing/padding and audio joins remain available.
5. Inspect actual frames and decoded media. Record unheard sound as unobserved. Execution completion is separate from visual review, listening and delivery approval.

Apply project-specific narrative rules only when the current project contract actually identifies that series. There is no universal cultivation, growing or cooking opening.
